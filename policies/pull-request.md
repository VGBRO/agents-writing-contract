# Pull Request Writing Policy

Route here from AGENTS.md when writing PR descriptions.

## Structure

Paragraph 1 — what changed and why.
  Name the problem. State the fix. One paragraph, no headings.

Paragraph 2 — test plan.
  List what you ran and what you checked. Bullet list is fine here.

## Limits

Description: under 200 words.
Test plan: under 100 words.

## What to avoid

- "This PR..." as an opener. Start with the change itself.
- Restating the commit message. Add what the commit does not say.
- Future tense for completed work. Write "adds" not "will add".
- Tagging reviewers in the description body. Use the reviewer field.
